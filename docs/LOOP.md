# 루프 엔지니어링 명령어 가이드

Todolist 프로젝트를 반복 실행으로 완성하기 위한 명령어 정리. `/goal` 항목은 공식 문서(code.claude.com/docs/en/goal)에서 확인한 내용이다.

## 1. 방식 비교

| 방식 | 반복 기준 | 적합한 경우 |
|---|---|---|
| `/goal <조건>` | 조건이 충족될 때까지 다음 턴을 자동 이어감 | 이 프로젝트처럼 "TODO 전부 완료"라는 종료 조건이 있는 작업 |
| `/loop <간격> <프롬프트>` | 시간 간격마다 프롬프트 재실행 | 배포 상태, PR 확인 같은 주기적 폴링 |
| `loop.sh` (셸 루프) | 매 회차 새 세션으로 `claude -p` 실행 | 회차마다 컨텍스트를 비우고 싶을 때 (Ralph 방식) |

공식 문서는 `/goal`과 `/loop`의 조합 방법을 다루지 않는다. 둘을 섞어 쓰는 것은 보장되지 않는다.

## 2. /goal 사용법

### 명령어
- 설정: `/goal <조건>` (조건은 최대 4,000자). 설정 즉시 조건을 지시문으로 삼아 턴이 시작된다.
- 상태 확인: `/goal` (조건, 경과 시간, 평가 턴 수, 토큰 사용량, 최근 평가 사유)
- 해제: `/goal clear` (별칭: `stop`, `off`, `reset`, `none`, `cancel`)
- `/clear`로 새 대화를 시작하면 활성 목표도 사라진다.

### 동작 방식
- 매 턴이 끝날 때 작은 모델이 조건 충족 여부를 판단한다. 미충족이면 사유를 다음 턴 지침으로 삼아 계속하고, 충족되면 자동 해제된다. 달성이 불가능하다고 판단되면 사유와 함께 해제된다.
- 세션당 활성 목표는 1개이며, 새로 설정하면 기존 목표를 대체한다.
- 판정 사유는 Ctrl+O로 볼 수 있다.
- 평가자는 도구를 실행하거나 파일을 읽지 않고 대화에 나온 내용만 본다. 조건은 Claude가 대화 안에서 증명할 수 있어야 한다.
- `/goal`은 권한 모드를 바꾸지 않는다. 무인 실행은 auto mode에서 `/goal`을 실행해야 한다.
- `--continue`, `--resume`으로 세션을 재개하면 진행 중이던 목표가 복원된다 (턴 수와 타이머는 초기화).

### 좋은 조건의 요건
1. 측정 가능한 종료 상태 하나
2. 확인 방법 명시 (명령어와 기대 결과)
3. 지킬 제약
4. 범위 제한 (예: "or stop after 20 turns")

### 이 프로젝트용 조건 예시
```
/goal TODO.md의 모든 항목이 [x]이고, npm run lint, npx tsc --noEmit, npm run build가 모두 종료 코드 0으로 통과한 출력이 대화에 표시된다. docs/SPEC.md에 없는 기능은 추가하지 않는다. 또는 30턴 후 중단한다.
```

### 비대화형 실행
```bash
claude -p "/goal <조건>"
```
- 목표가 끝날 때까지 한 번의 호출로 실행된다.
- 기본 텍스트 출력은 마지막에 한꺼번에 나오므로 멈춘 것처럼 보일 수 있다. 진행 상황을 보려면 `--output-format stream-json --verbose`를 추가한다.

### 목표가 해제되는 오류 (수정 후 다시 설정)
인증 실패, 크레딧 소진, 압축으로 해결되지 않는 컨텍스트 오버플로, 모델 사용 불가.
속도 제한과 일시적 오류는 일시정지 후 재시도하며 목표는 유지된다.

### 제약
- `disableAllHooks`가 `true`이거나 managed settings에 `allowManagedHooksOnly`가 있으면 사용할 수 없다.
- 필요한 최소 버전은 공식 문서 본문에서 확인하지 못했다. `claude --version`으로 확인한다.

## 3. 그 밖의 명령어
| 명령어 | 용도 |
|---|---|
| `/loop 5m <프롬프트>`, `/loop <프롬프트>` | 고정 간격 / 모델이 간격을 정하는 동적 반복 |
| `/schedule` | 클라우드 예약 실행 |
| `claude -p "<프롬프트>"` | 비대화형 1회 실행 |
| `--max-turns`, `--allowedTools`, `--output-format`, `--continue` | 반복 횟수, 권한, 출력 형식, 세션 이어가기 |
| `/clear`, `/compact`, `/context`, `/cost` | 컨텍스트와 비용 관리 |
| `/permissions`, `/hooks`, `/init` | 권한, 훅, CLAUDE.md |
| `/sc:workflow`, `/sc:task`, `/sc:test`, `/code-review`, `/simplify` | 작업 분해, 테스트, 리뷰 |

## 4. 프로젝트 검증 명령어
- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`

## 5. 문서 구성
| 파일 | 역할 |
|---|---|
| `CLAUDE.md` | 프로젝트 규칙 |
| `docs/SPEC.md` | 요구사항 |
| `TODO.md` | 작업 체크리스트 |
| `PROMPT.md` | 매 회차 프롬프트 (`loop.sh`, `/goal` 모두 이 순서를 따른다) |
| `PROGRESS.md` | 회차별 기록 |
| `.claude/settings.json` | 사전 허용 명령어 |
| `loop.sh` | 셸 루프 실행기 |
